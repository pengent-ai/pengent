## アプリ要件定義タスクの構成

## 全体ワークフロー(処理フロー)

```
[フェーズ1：アプリ概要確定]
    ↓(spec.md / spec.json)
    [ヒアリングエージェント]
        ↓ (HearingSheet)
    [ドキュメント作成エージェント]
        ↓ (Markdown, PDF, JSON)
    [アップロードツール]
        ↓
    [クラウドストレージ or DB]
    ↓
[フェーズ2：初回提案書の作成]
    ↓(draft_proposal.md)
    [顧客打ち合わせ・フィードバック]
        ↓
    [最終提案書の作成 + 成果物定義]
        ↓
    [アップロード＆承認へ]
        ↓

```

### エージェント/ツールについて

#### ヒアリングフェーズ

* エージェント:ヒアリングエージェント
  * 目的:ユーザーや依頼者からアプリに関する情報を収集する
  * 入力:
    * 対話インタフェース or 事前テンプレート(ヒアリングシート)
  * 出力:
    * HearingSheet オブジェクト

ヒアリングシート構造例(JSON)

```json
{
  "app_name": "MyHealthTracker",
  "target_users": "健康志向の一般ユーザー",
  "core_features": ["歩数記録", "食事ログ", "睡眠分析"],
  "platform": ["iOS", "Android"],
  "business_goal": "健康管理サービスの促進とユーザーデータの収集"
}
```

#### 概要生成フェーズ

* エージェント:ドキュメント作成エージェント
  * 目的:ユーザーや依頼者からアプリに関する情報を収集する
  * 入力:
    * HearingSheet オブジェクト
  * 出力:
    * JSON形式の構造化情報(AppSpec)
    * Markdown形式のアプリ概要

```sh
{
  "title": "MyHealthTracker - アプリ概要",
  "description": "健康志向の一般ユーザー向けに開発された…",
  "features": [
    {"name": "歩数記録", "description": "日々の歩数を記録しグラフ表示します"},
    {"name": "食事ログ", "description": "食べたものを記録し、栄養分析します"},
    {"name": "睡眠分析", "description": "睡眠時間と質を記録して可視化します"}
  ],
  "platforms": ["iOS", "Android"],
  "goal": "健康習慣の定着とライフログの収集"
}
```

#### 成果物アップロードフェーズ

* ツール:`アップロードツール`

* 処理:
  * `Markdown` → `PDF` に変換(例:`pandoc`や`markdown-pdf`)
  * JSONと共にクラウド保存(GCS, S3, Dropboxなど)

##### 保存形式とファイル

```
/apps/MyHealthTracker/
├── spec.md          # Markdown概要書
├── spec.pdf         # PDF版
└── spec.json        # 構造化JSON概要
```
