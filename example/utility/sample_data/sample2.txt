API認証について(詳細ガイド)

本APIでは、セキュアなアクセスを保証するために、Bearerトークン方式の認証を採用しています。これは、OAuth2の「Password Grant」または「Client Credentials」などに類似した仕組みで、アクセストークン(access_token)を取得し、それをHTTPリクエストのヘッダーに含めることで、各種エンドポイントにアクセスする方式です。

■ Authorizationヘッダーの形式

API呼び出し時には、HTTPヘッダーに以下の項目を追加してください：

```

Authorization: Bearer \<YOUR\_ACCESS\_TOKEN>

```

`<YOUR_ACCESS_TOKEN>` の部分には、事前に取得したトークン文字列(JWTやランダム文字列など)を埋め込みます。このトークンは認証サーバーで発行された有効なものでなければなりません。

■ トークンの取得方法

トークンは以下のエンドポイントから取得できます：

```

POST /auth/token

````

このエンドポイントは、以下の2つのパラメータを必要とします：

- `username`: 登録済みのユーザー名(メールアドレスでも可)
- `password`: 8文字以上のパスワード(英数字推奨)

■ リクエストボディの例(JSON形式)：

```json
{
  "username": "user@example.com",
  "password": "securePass123"
}
````

■ レスポンス例：

```json
{
  "access_token": "XXXXXXXXXXXXXXXXXXX...",
  "token_type": "bearer",
  "expires_in": 86400
}
```

`access_token` は実際の認証トークンで、以降のAPI呼び出しで `Authorization` ヘッダーに含めます。
`expires_in` はトークンの有効期限(秒単位)で、通常24時間(86400秒)です。

■ トークンのリフレッシュ・再発行

有効期限が切れた場合は、再度 `/auth/token` に同じ情報を送って新しいトークンを取得してください。セキュリティ上の理由から、トークンは自動的に延長されません。

■ トークンが無効な場合のレスポンス

トークンが無効・期限切れ・存在しない場合、すべてのAPIは以下のようなエラーレスポンスを返します：

```json
{
  "detail": "Unauthorized"
}
```

HTTPステータスコード：`401 Unauthorized`

■ セキュリティのベストプラクティス

* アクセストークンは絶対にクライアントにログ出力しないでください。
* HTTPS(TLS)接続を強制し、トークンの盗聴を防止してください。
* クライアント側ではトークンを短期保存し、再利用時には期限切れをチェックしてください。
* WebアプリではHTTPヘッダーによるセッション管理よりも、トークンベースのREST呼び出しを推奨します。

■ トークンの権限スコープ(オプション)

一部のAPIでは、発行されるトークンに「スコープ(scope)」を指定することで、アクセス範囲を制限できます。

例：

```
scope: ["read:project", "write:task"]
```

今後の拡張として、ユーザーロールやスコープベースのアクセス制御が導入される予定です。
